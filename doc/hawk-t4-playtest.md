# Плейтест: triplebox Hawk «ttt», T4 Raging Dark, комната 3 под ботом

Сценарий: пользователь проходит комнаты 1–2 руками (3 клиента), в комнате 3 даёт отмашку —
Claude через MCP (`src/AbotMcp`) заходит и доводит комнату ботом под живым супервизором.
Тактика: abyss_lurkers_ref/HAWK-TRIPLEBOX-GUIDE.md. Fleet-дисциплина: оба wing-хоука держат
Orbit на Gil-Gelad (лид/танк), Gil орбитит маяк/кэш на дефолтной орбите (25 км в настройках
клиента — это же и кайт-дистанция).

## Что добавлено в код (2026-09-04)

- `FitsRegistry.HawkTTT` — маппинг фита «ttt» (лончеры СГРУППИРОВАНЫ в одну кнопку + рельса
  отдельно ⇒ 2 кнопки в верхнем ряду; миды: SB / батарея / кап-инжектор / AB / SB).
- `ProfilesRegistry.Hawk_T4` — профиль (`--profile Hawk_T4`), филамент «Raging Dark Filament».
- `ShipFit.ModuleType.CapBooster` + `ShipFit.AttackRange`; AB = `AlwaysOn` (входит в
  GetAlwaysActiveModules ⇒ бот держит его включённым всегда).
- `ShipState.GetNextTankingModulesTask` ОЖИВЛЁН (раньше был мёртвый `return null`):
  кап-инжект при cap < 35%; щит < 60% ⇒ один SB (dps ≤ 150) или оба; щит > 85% или
  cap < 20% ⇒ SB выкл (гистерезис 600–850‰).
- Позиционирование: клик top-level «Orbit» без сабменю ⇒ дефолтная орбита клиента; корабль
  уже в манёвре Orbit (wing на лиде) НЕ переорбичивается стратегией.
- Перегрев НЕ автоматизирован (риск спалить) — супервизор ставит/снимает overload вручную
  shift-кликом по кнопке SB через MCP `click(id, modifiers:["shift"])`.

## Подготовка (до входа в абисс!)

1. Сгруппировать 4 лончера в HUD на всех трёх хоуках (иначе маппинг фита не сойдётся).
2. Оверью-таб должен показывать врагов И флитмейтов (wing-хоукам нужен Gil-Gelad в оверью,
   чтобы поставить орбиту через контекст-меню).
3. Запустить сервер из корня репо: `dotnet run --project src/AbotMcp -- --live --profile Hawk_T4`.
4. В Claude Code: `/mcp` reconnect на `abot`; затем `attach_clients` СРАЗУ (первый attach
   каждого клиента = скан UIRoot 10–90 с — делать до захода в абисс, лучше на станции).
5. Проверка маппинга: `get_ui ship` на каждом клиенте — 3 ряда, верхний = 2 кнопки
   (группа лончеров первой слева, иначе поправить порядок в `FitsRegistry.HawkTTT`),
   миды 5 в порядке SB/батарея/инжектор/AB/SB (сверить по ChargeTypeId: инжектор = Navy
   Cap Booster 400).

## Передача управления (комната 3)

1. По отмашке: `status` всех трёх → wing-1, wing-2: `context_menu` по оверью-entry
   «Gil-Gelad» → «Orbit» (дефолт 25 км — ок по словам пользователя).
2. `autopilot start` на всех трёх (intervalMs ~2000). Ввод сериализуется общим мьютексом.
3. Супервизия циклом `watch`/`status` (танк — приоритет): щит лида < ~30% ⇒ shift-клик по
   обоим SB (overload ON), после отхила снять overload и заметить нанит-пасту на ремонт.
   Развал ситуации ⇒ `emergency_stop`.
4. Комната зачищена: `autopilot stop` на wing-ах (чтобы не рвались лутать), кэш добить/
   залутать Gil-ом (бот или вручную), затем «Activate Gate»/выход — каждым кораблём.

## Разбор первого захвата управления (2026-09-04, комната 3, EDENCOM)

Бот НЕ воевал: 327 NRE за бой — `ShouldInjectCap` читал `ShipUi.HitpointsAndEnergy`,
который **Eve64-парсер не заполняет** (он пишет `HitpointsPercent` и
`Capacitor.LevelFromPmarksPercent`, в **процентах 0–100**, а не в промилле). Исключение
убивало `CombatTask.Component` на первом же звене (танковка идёт раньше стрельбы), поэтому
не работали ни бустеры, ни оружие, ни локи — «Fenreire не стреляет» было симптомом того,
что бот целиком мёртв. Старая танк-логика была dead code (`return null`), поэтому баг
никогда раньше не всплывал.

Исправлено: `IShipUi` расширен `HitpointsPercent`/`Capacitor` (+прокидка в Parse-обёртке),
вся танк-логика переведена на проценты (щит<60 → буст, >85 → выкл, кап-модель на долях),
нечитаемые датчики = «ничего не делать», `SimpleTargetInfo.Distance` не падает на
null-дистанции свежего лока. Что подтвердилось живьём: Regroup=Orbit не сбивается ботом,
маппинг фита, аттач/чтение трёх клиентов под боем, кайт лида на дефолтной орбите.

## Известные допущения / риски

- Кэш (Bioadaptive Cache) может не быть «красным» ⇒ бот его не стреляет — тогда добить
  вручную рельсой Gil-а (click по кнопке рельсы при залоченном кэше).
- Порядок кнопок в верхнем ряду (группа vs рельса) не проверен живьём — шаг 5 подготовки.
- Танк-пороги (‰) не калиброваны на реальном T4 — супервизор компенсирует вручную.
