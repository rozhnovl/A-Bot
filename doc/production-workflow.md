# Производственный помощник — состояние и план (13.09.2026)

Основной источник фактических игровых операций — EVE ESI; локальная SQLite хранит планы, цены получения, ручные подтверждения и снимки ESI. Отдельный контейнер для одного сервера не нужен. Старый `production.db` с демоданными не изменён; новая база `src/WebUI/WebUI/production-v2.db` создаётся при первом запуске.

## Готово

- Ресурсы со средневзвешенной ценой, работы и закупки с привязкой к ним, продажи со сверкой себестоимости, комиссий/налогов и прочих затрат. Месячная цель по умолчанию — **10 млрд ISK чистой прибыли**. Burndown отделяет сверенную прибыль от явно оценённой чистой прибыли открытых работ; несверенные продажи и работы без оценки отмечены отдельно. Потенциальная выручка активных sell-ордеров ESI показана отдельно.
- `POST /api/production/events` с API-ключом и обязательным стабильным `eventId`; повторная доставка не дублирует событие. `GET /api/production/plan` даёт машиночитаемый план для агента: цель, факт, потенциал открытых работ со сроком в этом месяце, разрыв, нужный дневной темп, открытые работы и закупки. `GET /api/production/snapshot` даёт полный локальный снимок.
- EVE SSO на `/esi`: серверный Authorization Code flow, проверка временного `state` и персонажа, сохранение refresh token через ASP.NET Data Protection. Фоновый опрос каждые 5 минут сохраняет wallet transactions, wallet journal, industry jobs, character active/history orders и assets с ETag/expiry и устойчивыми ID. Многостраничные наблюдения публикуются только после полного прохода; неполный проход не заменяет прежний видимый снимок. Только личные sell wallet transactions становятся подтверждёнными продажами; себестоимость остаётся неизвестной. Orders/assets/jobs не превращаются автоматически в расход или выручку.
- `GET /api/production/esi/status` и `GET /api/production/esi/records?kind=WalletTransaction|WalletJournalEntry|IndustryJob|Order|Asset&limit=100` доступны с тем же API-ключом. Статус включает последний успешный опрос и ошибку текущего процесса, не стирая ранее полученные наблюдения. `/api/production/plan` включает отдельные `sellOrders` и `observedTradingFees`. По ним агент может проверять источники и свежесть данных перед планированием.

## Подключение

1. Локальный HTTPS профиль уже настроен на `https://localhost:7297`, а в Development задан callback `https://localhost:7297/esi/callback`. Сертификат разработчика создан, но не добавлен в доверенные. Для запуска используйте `dotnet run --project src/WebUI/WebUI/WebUI.csproj --launch-profile https`; если браузер не доверяет сертификату, владелец машины может проверить и доверить его командой `dotnet dev-certs https --trust`. Не обходите предупреждение браузера вручную. Если портал EVE не принимает loopback callback, нужен публичный HTTPS-хост с точным соответствующим адресом.
2. Войти своим CCP-аккаунтом на [EVE Developers](https://developers.eveonline.com/) и зарегистрировать web-приложение с callback `https://localhost:7297/esi/callback` и scopes `esi-wallet.read_character_wallet.v1`, `esi-industry.read_character_jobs.v1`, `esi-markets.read_character_orders.v1`, `esi-assets.read_assets.v1`. Без входа владельца нельзя получить действительные Client ID/secret; не отправляйте секрет в чат.
3. Задать в переменных окружения/secret store: `Esi__ClientId`, `Esi__ClientSecret`, `Esi__OperatorEmail` (email учётной записи WebUI, которой разрешено выдавать EVE SSO согласие), `Production__ApiKey`, а также `Esi__UserAgent` с названием и контактным адресом. `Esi__RedirectUri` в Development уже установлен, в другом окружении его нужно задать отдельно. Удобно локально использовать `dotnet user-secrets set "Esi:ClientId" "<id>" --project src/WebUI/WebUI/WebUI.csproj` и аналогично для `Esi:ClientSecret`, `Esi:OperatorEmail` и `Production:ApiKey`; значения остаются вне Git. При необходимости зафиксировать одного владельца через `Esi__CharacterId`; сейчас синхронизируется один персонаж. OAuth `state` привязан к оператору, живёт 10 минут и принимается один раз.
4. Указать `DataProtection__KeysDirectory` — приватный постоянный каталог с резервной копией и правами только серверной учётной записи. На Windows ключи защищаются DPAPI текущего пользователя. SQLite и key ring должны быть вне публичной статики. Для локального запуска каталог по умолчанию `.data-protection-keys/` исключён из Git.
5. При первом запуске в Development миграция создаёт локальную Identity-базу WebUI. Зарегистрировать собственную учётную запись на `/Account/Register` с email, совпадающим с `Esi__OperatorEmail`, подтвердить её и войти; пароль вводить только в WebUI, не в чат и не в репозиторий. В текущем шаблоне реальной отправки писем нет: ссылка подтверждения показывается на странице регистрации, поэтому этот механизм пригоден только для локального запуска и не должен выставляться в интернет без настоящей проверки email и ограничения регистрации. Затем открыть `/esi` и выдать согласие через EVE SSO. Без согласия опрос работает как no-op; локальный план остаётся доступным. Для API использовать заголовок `X-Production-Api-Key`, никогда URL.

## Расчёт и пределы

Факт цели = сумма `выручка − количество × себестоимость единицы − комиссии/налоги − прочие затраты` по продажам, где все три компонента затрат указаны. Нулевые затраты должны быть подтверждены явно. Личные sell wallet transactions (`is_personal=false` пока пропускается) приходят из ESI как **несверенные**: API не даёт достоверную себестоимость assets и реально списанный BOM, а общие списания журнала нельзя безопасно разнести по продажам автоматически. Вручную сверяйте их на странице «Продажи», включая относящиеся к ним производственные расходы в себестоимость или прочие затраты. Прогноз = сверенная прибыль + явно указанная ожидаемая чистая прибыль открытых работ со сроком в этом месяце; это сценарий, не факт. При неполных данных показатели отражают только сверенную часть. Если бот отправит ту же продажу под другим `clientId/eventId`, что и ESI, возникнет дубль.

## Следующие итерации

1. Точная привязка wallet journal комиссий/налогов к сделкам, метрики полноты каждого endpoint; корпоративный контур, если владельцем производства является корпорация. Сейчас подтверждённые дебетовые проводки `brokers_fee`, `transaction_tax`, `market_provider_tax`, `market_security_tax` считаются отдельно, без вычитания из валовой прибыли.
2. `type_id` в локальных позициях, имена и BOM из официального SDE, привязка `job_id` к работе, партии ресурсов и метод распределения себестоимости. После этого — подтверждённая прибыль.
3. Миграции SQLite вместо `EnsureCreated`, расширение проверок целостности снимка при смене `X-Pages`, автоматические тесты отзыва scope, 429 и ротации refresh token. Базовые проверки SQLite/ESI уже есть: `dotnet run --project tests/Production.Integration/Production.Integration.csproj`.

Основание для scopes и ограничений: [официальная схема ESI](https://esi.evetech.net/meta/openapi.json?compatibility_date=2026-09-13), [SSO](https://developers.eveonline.com/docs/services/sso/), [ESI best practices](https://developers.eveonline.com/docs/services/esi/best-practices/). Подробная карта полей — в `production-esi-plan.md`.
